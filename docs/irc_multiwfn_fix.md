# IRC 添加键级曲线时 Multiwfn 卡住的修复

在 IRC 页面读取能量数据后点击“添加键级曲线”，原调用可能在同一个文件的
文件选择提示处等待，用户看到反复弹窗或计算一直不结束。修复后，程序通过
启动参数明确指定 fchk 文件，完成键级计算并退出；再次添加不同原子对的曲线
会复用已有的全部 Mayer 键级表，并保留先前的曲线。

## 原因与复现

调用链为 `IrcPanel._add_bond()` → `IrcBondWorker.run()` →
`calculate_mayer_bond_order()`，源码位于 `molstudio/panels/irc_panel.py`。

原函数只用 `[multiwfn_path]` 启动 Multiwfn，向标准输入发送：

```text
<空行>
<fchk 文件名>
9
1
n
0
q
```

实测 Multiwfn 2026.4.10 在“输入文件路径”阶段将空行解释为
“打开 GUI 文件选择窗口”。隔离启动测试卡在该提示，3 秒后由测试脚本主动
终止；它没有按预期加载文件并进入键级分析。该问题在原打包 EXE 的内嵌
IRC 代码中也存在。

worker 本身是有限的逐文件循环，没有无限重试；但原函数会静默捕获调用错误，
继续处理下一个文件，导致相同的启动失败在批处理中重复出现。

## 修改

1. 启动参数改为 `[multiwfn_path, fchk_name]`，工作目录仍为输入文件所在目录。
   标准输入仅负责菜单序列，复用 `charge_viewer.BO_INPUT_SEQ`。菜单序列中的
   开头空行保留；由于文件已作为参数加载，它不再落到文件路径提示上。
2. 复用 `_run_multiwfn_subprocess()`，沿用 Windows 的管道、
   `CREATE_NO_WINDOW` 和 `CREATE_NEW_PROCESS_GROUP` 配置。
3. 超时、异常退出或缺少有效 Mayer 结果时抛出错误，worker 记录原因并停止
   后续文件；未完成的点以 `None` 补齐，保证结果与能量数据一一对应。
4. 缓存须包含键级表标题及键级结果行，仅有菜单或启动提示的内容不再被复用。
   缓存仍按输入文件路径保存全部原子对的键级，可供其他原子对读取。
5. 移除错误槽中的 `setattr(button, "setEnabled", True)`，避免覆盖方法。
   完成信号负责恢复按钮。
6. 添加曲线时保留已有键级曲线并分配不同颜色；完全失败时保留原图。
   电荷曲线与键级曲线仍按原设计互斥。

## 验证

### 自动回归测试

```bash
python -m pytest tests/test_irc_bond_order.py -q
```

结果：**8 passed**。测试无需安装 Multiwfn，覆盖文件启动参数与 Windows
flags、跨原子对缓存复用、无效缓存重算、超时/异常退出/无效输出后的停止行为，
以及新增曲线和完全失败时保留已有曲线。

### 真实 Multiwfn 与 IRC 数据

使用 Multiwfn **2026.4.10 Win64** 和 25 个实际 IRC fchk 文件。
输入与配置复制到隔离目录，未替换原安装 EXE 或原测试数据。

| 检查 | 结果 |
| --- | --- |
| 能量提取 | 25/25 成功 |
| 第一次键级计算 | 25/25 成功，所有进程以退出码 0 结束，计算总耗时约 3 秒 |
| 原子对 1–2 与 1–3 | 两条曲线各有 25 个有效点 |
| 第二条曲线的新增 Multiwfn 调用 | 0，全部复用缓存 |
| 打包环境的 IRC 按钮流程 | 离屏构造原版面板并实际触发按钮，计算、双曲线保留及绘图通过 |
| 打包环境模拟超时 | 首个调用失败后停止批处理，恢复按钮并保留已有曲线 |

打包验证基于用户现有 EXE 的模块与运行库，仅将四个 IRC 函数替换为本次修复；
这验证了已有打包环境的兼容性，没有将当前 GitHub 源码重新构建为完整安装包。

### 全套测试的已有失败

```bash
python -m pytest tests -q
```

修复后为 **9 passed, 4 failed**；同一环境下未修改的基线为
**1 passed, 4 failed**。相同的四项失败为：

- 三项主窗口/界面测试遇到 `_PopupLimitedComboBox` 的 `max_popup_height`
  未识别关键字参数错误。
- 子模块导入测试遇到 `molstudio/render/ovcanvas/_glwidget.py` 中
  `GL_LESS` 未定义。

这些问题不属于本次 IRC 修改。验证覆盖 IRC 面板流程，尚未对整个程序其他
功能进行完整回归。用户的 fchk、测试日志、安装文件和修复 EXE 不随源码提交。
