# MolStudio 新界面说明（Clean Light / Bridge 两套皮肤）

给 MolStudio 加了一套 **Demo 1「Clean Light」浅色卡片风** 的界面，**旧的界面完整保留**，
两套界面共用同一份功能代码，随时可以切。

后来在 Clean Light 基础上、参照另一个项目 **xTBridge Lite** 的界面语言，又加了一套
**「Bridge」皮肤**（`main_window_clean2.py`）：色调更冷（强调色 `#2F6FED`、窗口底 `#F4F6FA`）、
圆角收紧一档（卡片 12 / 控件 8），并在最上方多了一条 **标题栏**（品牌名 + 副标题 + 状态胶囊）。
两套新皮肤与旧界面并存，用 `--ui` 选。

---

## 一、怎么用

```powershell
cd "D:\OrbitalViewer 5.3"

# 新界面（Clean Light 皮肤）
python main.py --ui clean
python main_window_clean.py          # 等价的独立入口

# 新界面（Bridge 皮肤，xTBridge Lite 风）
python main.py --ui clean2
python main_window_clean2.py         # 等价的独立入口

# 旧界面（默认，行为与以前完全一致）
python main.py
python main.py --ui classic

# 也可以用环境变量指定默认值（--ui 优先级更高）
$env:MOLSTUDIO_UI = "clean"; python main.py
$env:MOLSTUDIO_UI = "clean2"; python main.py
```

新界面窗口里按 **Ctrl+Shift+U** 可以另起一个进程开回旧界面（不影响当前窗口）。

命令行批处理模式不受影响，`--ui` 会在解析前被摘掉：

```powershell
python main.py input.fchk --mo h --ui clean    # --ui 被摘走，批处理参数照常
```

## 三、实现方式：子类继承，不复制功能

新窗口**没有**重写界面代码，而是：

```python
class MolStudioCleanWindow(OrbitalVisApp):
    def _apply_theme(self):
        self.setStyleSheet(CLEAN_QSS)      # ← 只换主题

    def _setup_ui(self):
        super()._setup_ui()                # ← 16 个 tab、全部面板与信号接线都在这里建立
        self._apply_clean_skin()           # ← 只做视觉后处理
```

这样做的关键好处：**「链接所有功能」是自动成立的**。左侧导航 → 页面栈的联动、
每个分析面板拿到的 `glw` / `get_fchk` / `log_func` 回调、面板之间的双向同步
（如 IGMH ↔ VMD 控制区）、快捷键、拖放、语言切换，全部由父类原样建立，
不存在「新界面漏接了某个按钮」这种风险。

### 皮肤后处理具体做了什么

1. 顶部输入行 → 无标题圆角卡（`objectName = InputCard`）
2. 左侧导航卡加宽 122 → 150px，条目改成圆角胶囊选中态
3. 中间画布区 → 白色圆角卡，内部留 8px padding 形成「凹陷视口」
4. 右侧 16 个功能页 → 加内边距，内容不贴圆角边线
5. 主布局外边距 12,8,12,10 → 10,10,10,10，间距 6 → 10
6. 分割条比例按导航新宽度重算
7. **局部配色重映射**（见下）

### 最有价值的一处：局部配色重映射

15 个分析面板里散落着 **92 处 `setStyleSheet`**（`ovcanvas/_panel.py` 13 处、
`esp_panel.py` 12 处、`energy_span_panel.py` 17 处……）。Qt 里**控件自身的样式表
优先级高于祖先窗口**，所以只换全局主题的话，会出现「外壳是新皮肤、里面的面板
还是旧的深蓝色」的割裂感。

`main_window_clean.py` 里的 `_COLOR_REMAP` 把旧配色表整体映射到新配色：

```python
"#1565c0": "#2563eb",   # 主色
"#0d47a1": "#1d4ed8",   # 主色深
"#cbd5e1": "#e2e8f0",   # 边框
"#e4eaf2": "#eef2f7",   # 窗口底
...
```

只映射**界面构件色**（主色 / 边框 / 底色 / 文字），**不碰**元素色、轨道相位色、
色标这类语义颜色，所以分子配色不会被改坏。实测 93 个带局部样式的控件里，
旧主色 `#1565c0`、旧边框 `#cbd5e1` 已经清零。

切换语言、切换渲染风格时会重建一批局部样式，所以这两个入口也做了覆写，
跟着重新映射一次，皮肤不会「用着用着变回旧色」。

## 四、两个刻意的取舍

### 1. 卡片没有加投影

Demo 1 的观感里 `QGraphicsDropShadowEffect` 投影很关键，但**这套界面不能用**：
窗口里内嵌 `QOpenGLWidget`，而且这个 GL 控件会在各分析面板之间**被反复重新 parent**
（`main_window.py` 里大量 `glw=self.cub_canvas.glw` 的写法）。图形效果会强制控件走
QPainter 软件合成，导致 QOpenGLWidget 渲染异常或整块黑掉。

所以这里只用 **1px 描边 + 圆角 + 浅灰窗口底** 来分层。视觉效果略逊于 Demo 1，
但绝不动 GL。如果你以后想要投影，唯一安全的做法是先给画布换成独立顶层窗口
（`QOpenGLWidget` 不放在被加效果的控件子树里）。

### 2. 新窗口加了一道「收进屏幕」的保险

父类按 `1400x820` 设计、最小 `1100x680`。新窗口额外做了两件事：

- 最小尺寸放宽到 `1080x620`；
- 首次显示时，如果窗口比可用屏幕区域还大，就自动收到屏幕内。

**在你这台机器上这两条都是空操作**——实测主程序的真实运行环境是
**2560×1368 可用、dpr=1、logicalDpi=144（字体 1.5×）**，1400×820 和 1100×680
都放得下。加它们只是为了万一把程序拿到小屏笔记本上跑时不至于顶出屏幕。
**只影响新界面**，旧界面的尺寸逻辑没动。

> 这里更正一个我先前说错的地方：我早前用探针测到「屏幕逻辑区只有 1280×684」，
> 那是因为探针自己开了 `AA_EnableHighDpiScaling`（dpr=2），而 **`main.py` 并没有开**，
> 所以真实环境是 2560×1368 @ dpr=1。结论应该是「旧窗口放得下」，不是「放不下」。

## 六、已知限制

1. **GL 画布在无显示环境下是空白**。上面的对比截图是用
   `Qt.WA_DontShowOnScreen` 离屏渲染的，`QOpenGLWidget` 在离屏状态不渲染，
   所以截图里中间画布是空的。**真正跑起来（`python main.py --ui clean`）
   三维分子照常显示**。
2. **配色重映射是字符串级替换**。如果以后有面板用了恰好等于映射表键值的
   语义颜色，会被一并改掉。新增面板时如果发现颜色不对，把这几个 hex 从
   `_COLOR_REMAP` 里摘掉即可。
3. **两套界面不能在同一个进程里来回切**。`_apply_theme` 是实例级的没问题，
   但 GL 上下文只有一个，同时开两个主窗口容易出问题。所以切回旧界面走的是
   「另起一个进程」（Ctrl+Shift+U）。
4. 还没往 `CHANGELOG.md` 里加条目 —— 那个文件你本地已有未提交改动，
   我没动它，避免和你的编辑冲突。

## 七、第二轮：按实测差距做的三处改造

第一版做完后，我用脚本把 Demo 1 和这个窗口的设计指标逐项测了一遍（`_compare_style.py`
/ `_compare_style2.py`），找出「为什么 Demo 看起来更好看」的可量化原因，然后针对性地补了三处。

### 实测差距（改造前）

| 指标 | Demo 1 | 主程序 | 说明 |
|---|---|---|---|
| 可交互控件总数 | 47 | **412** | 9 倍信息量铺在同样面积上 |
| **导航条目带图标** | **8 / 8** | **0 / 16** | 纯文字导航像表单，不像应用 |
| **带图标的按钮** | **17** | **0** | 全窗口一个图标都没有 |
| **QGroupBox（蓝底白字标题徽章）** | 0 | **36** | 强调色被用成底色，等于没有强调 |
| 布局平均间距 | 4.6px | 3.3px | 更挤 |

### 改造 1：图标（收益最大）

新增 `ui_icons.py`：**43 个纯 QPainter 现画的矢量图标**，零图片资源、零字体文件，
所以**不增加打包体积**，也不会有 PyInstaller 下资源路径找不到的问题。

- **左侧导航 16 项各配一个不同图标**（`NAV_ICONS` 映射表），并写入 QIcon 的
  Selected 状态，选中时图标从灰变蓝，跟文字高亮同步；
- **按钮图标用「文字关键词识别」批量配**（`BUTTON_ICON_RULES`）：中英文关键词都覆盖，
  遍历控件树自动匹配。实测 **159 个有文字按钮里配上了 98 个**，覆盖全部 16 个功能页，
  而且**一个面板文件都不用改**；
- 两条安全规则：已经自带图标的不动；文字以 emoji/符号开头的不动
  （如 `⚙️ 路径设置`、`＋ 添加物种`），否则会变成难看的「双图标」。

图标对照图：`ui_demos/shots/icons.png`（`python _icon_sheet.py` 重出）。

### 改造 2：36 个蓝色标题块 → 无边框分区

原来每个分组框都是 `QGroupBox` + 蓝底白字标题徽章。蓝色本该是强调色，
撒了 36 个之后反而不强调任何东西，界面看着就"糙"。

现在改成**无边框分区**：只有一行加粗深色标题 + 留白，靠字号和层级分节，
不再用色块。容器型的两个分组框（VMD 控制台 / AIM 出图）单独保留卡片外观。

顺带加上了**点标题即折叠**：

- 用**事件过滤器**实现（`_SectionClickFilter`），不改控件类型、不改控件树结构，
  所以 15 个面板文件依然一行不动；
- 折叠时**先记录子控件的当前可见性再隐藏**，展开时按记录还原 ——
  这样面板自己故意隐藏的控件不会在展开时被错误地显示出来（实测 14 个直系子控件
  折叠 → 展开后可见性完全一致）；
- 空标题的分组框会被跳过（它顶部 28px 里放的是真实控件，装过滤器会吞掉点击）；
- 可勾选的分组框也跳过。

> 默认**全部展开**，没有替你猜哪些是"高级参数"。要不要默认折叠、折叠哪些，
> 取决于你的真实使用习惯，这个建议你跑一阵子之后再定，我再改。

### 改造 3：字号层级收成 5 级

基础字号 9.5pt → 9pt（内容容量更大、更透气），标题 16pt → 15pt，
统一成 **15 / 10.5 / 9 / 8.5 / 8** 五级，层级差距明确。

### 改造 3.1：修掉「输入文件」被藏起来（改造 2 的回归）

改造 2 把通用 `QGroupBox` 改成「无边框透明分区」之后，顶部输入行的
`QGroupBox#InputCard` 没显式写背景与描边，于是**丢了白卡外观**；同时它的
`margin-top: 0` 让分组框标题（父类用 `setTitle("输入文件")` 写的）**没有留白可放、
被直接裁掉**。两件事叠在一起，看起来就是「输入文件这一行被隐藏了」。

现在改成行内标签形式，排布为：

```
输入文件   [ 路径框（自适应铺满） ]   [浏览] [EN] [⚙️路径设置] [关于]
```

- `#InputCard` 显式补回白底 + 1px 描边 + 圆角；
- 新增 `QLabel#InputLabel`，插在布局第 0 位，文字取自父类同一个 i18n key
  `grp_input`（中/英自动跟随，切语言时同步刷新）；
- 分组框标题清空，避免与行内标签重复、也彻底消除被裁切的可能；
- 插标签的做法是幂等的（重复调用只改文字，不会插第二个）；
- 附带好处：这一行不再是「有标题的分组框」，所以不会被装上点标题折叠的
  事件过滤器，输入行上的点击不会被吞掉。

### 还没做的两条（以及为什么）

**画布装饰**（渐变底 / 网格 / 角标文字）：实测 `QWidget.grab()` **抓不到
`QOpenGLWidget` 的画面**（离屏渲染时画布区域是纯色一片），也就是说我无法对这个
区域做视觉验证。往 GL 控件上面叠 QPainter 覆盖层的做法在 Qt 里通常可行，但
"通常可行" + "我验证不了" 不是我会替你做决定的组合。要做的话建议你在场，我改完你立刻看一眼。

**密度**（412 个可交互控件）：这是结构性的，不是样式能解决的。我给了折叠机制，
但没有替你决定默认折叠哪些 —— 这个得按你真实的使用频率来定。
